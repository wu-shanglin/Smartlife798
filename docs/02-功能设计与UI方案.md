# 功能设计与 UI/UX 方案

> 配套文档：[`01-逆向分析报告.md`](01-逆向分析报告.md)、[`03-技术方案与开发计划.md`](03-技术方案与开发计划.md)
> 设计原则：**业务能力对齐原服务端，页面结构、交互与视觉完全重做**，不复刻原应用布局。

## 客户端更新

登录页「检查客户端更新」和「我的 → 关于本客户端 → 检查更新」为手动入口；启动／回到前台自动检查（5 分钟合并）。发现普通更新可稍后，强制更新仅能下载／重新检查，返回、点击外部和登出不解除。点击「立即更新」在应用内下载 GitHub APK，显示进度、取消与失败重试；验证通过后打开系统安装器，首次引导未知来源授权。用户取消安装后保留「安装新版」入口；只有实际安装达标版本才解除限制。断网保留已知策略，无有效策略不误拦截；演示模式不联网或安装。发布控制与限制见 [docs/06](06-工程规范与路线图.md#github-更新发布)。

## 1. 设计目标

1. **重扫码、轻导航**：把"扫码 → 看设备 → 开始使用"压缩到 2 次点击内；扫码按钮常驻底部导航中央。
2. **状态可信**：所有设备状态、余额、账单都显示服务端返回值与更新时间，本地只做"索引与偏好"。
3. **一眼判断**：设备卡片/详情用统一状态色（在线/运行中/离线/禁用）与主按钮（立即使用/结束并结算）。
4. **弱网可读**：加载、空数据、网络异常、设备不可用、令牌过期都有明确页面态与可执行动作。
5. **现代 Material 3**：动态留白、圆角卡片、色调分层，日间/深色自动跟随系统。

## 2. 功能清单

### 应用图标

图标面向校园学生日常饮水、淋浴和洗衣使用，采用青绿底、米白屋檐、薄荷水滴及波纹，强调生活服务与易辨识。无文字和官方标志。使用 imagegen 内置工具生成，[源图](../artwork/app-icon.png)与[最终提示词](../artwork/app-icon.prompt.txt)保留供后续维护；Android 资源从源图做等比缩小，不拉伸或裁掉主体。

Manifest 使用 `@mipmap/ic_launcher`；API 24/25 提供五档密度 PNG，API 26+ 自适应前景/背景采用安全区构图，API 33+ 额外提供屋檐与水滴单色矢量轮廓。圆形与圆角方形由系统 mask 裁切，不在源图预先画圆角。

### 2.1 保留（对接原服务端）

| 功能 | 服务端能力 | 新客户端实现 |
|---|---|---|
| 手机号登录 | 图形码 + 短信 + `token` | 完整实现（图形码直接取服务端图片） |
| 自动登录 / 令牌失效 | `Authorization` + `code=-99` | 启动恢复令牌；`-99` 自动登出并提示 |
| 扫码识别 | `qr/use` | CameraX + ML Kit 扫码，本地预解析后交服务端确认 |
| 设备详情 | `dev/home/1` | 重绘为信息卡 + 状态区 + 操作区 |
| 设备实时状态 | `dev/status` 轮询 | 2s（启动中/运行中，含启动成功后 20s 受限窗口）；空闲/异常不轮询，仅前台运行，显示"更新时间" |
| 启动设备 | `dev/start` | 主按钮 + 支付方式选择 + 模式选择 |
| 结束并结算 | `dev/end` | 主按钮切换，结束后引导到订单页 |
| 切换模式 | `dev/mode/start` | 模式 Chip 组 |
| 收藏 / 取消 | `dev/favo`、`master.favos` | 详情页收藏按钮 + 设备页收藏分栏，双端一致 |
| 消费记录 / 账单详情 | `bill/lst-owner`、`bill/view-full` | 订单页"消费记录"分栏 + 底部详情面板 |
| 扫码失败兜底 | `qr/use` | **手动输入编号**（与扫码同一解析链路） |
| 账单支付（支付宝） | `bill/pay/channels`、`trans/prepay`、`trans/confirm` | 未付款账单详情顶部「去支付」（打开即见）→ 官方 Alipay SDK → 服务端确认 |
| 自动刷新 | — | 打开应用/切页/返回自动刷新，界面无刷新按钮 |
| 账号资料 | `master.account` | 我的页资料卡、积分、欠费 |
| 钱包余额与充值 | `acc/wallet/owner`（`data.aw`）、`prd/lst?type=1`、`bill/save` | 我的→钱包→服务端充值商品→创建账单→支付 |
| 微信支付 | `trans/prepay/11`、微信 SDK、`trans/confirm` | SDK 与回调已接入；平台配置与真实实付待验 |
| 支付宝免密签约 | `ui/app/sign-pga?type=20` | 优先 sign + SDK；不将协议渠道集合作为用户签约状态 |

### 2.2 新增（本地实现，关联真实设备）

| 功能 | 数据来源 | 说明 |
|---|---|---|
| 常用设备 | 收藏 ∪ 使用次数≥2 的设备，按"置顶 → 最近使用 → 使用次数"排序 | 次数来自云端账单聚合，置顶保存本机 |
| 最近使用 | `bill/lst-owner` 的 `dev` 聚合（服务端历史）+ 仅扫码未使用的本地记录 | 最多 60 条，单条可清除 |
| 设备搜索 | 名称 / 编号 / 类型 | 本地过滤，点击后打开真实详情 |
| 类型筛选 | 设备类型枚举 | 横向 Chip 组 |
| 统一异常反馈 | 网络、`-99`、`-87/-88/-52` 等 | Snackbar + 内联错误卡 |
| 深色模式 | 系统 | 全套色板与状态色适配 |

### 2.3 明确不做

- 云闪付/银行 SDK 支付；微信 SDK 已集成，开放平台配置及真实支付待验
- 门禁蓝牙开门、IC 卡读写、NFC、考勤打卡
- E 袋洗、驾考、积分商城、广告位
- 任何形式的"模拟开机/模拟计费"

### 2.4 本地数据与服务器数据边界

| 数据 | 存放 | 权威方 |
|---|---|---|
| 账号、收藏、设备状态、余额、账单、订单 | 服务端 | 服务端 |
| 令牌、手机号 | 本机 SP | 服务端签发 |
| 最近设备索引、置顶 | 本机 SP（JSON） | 索引本机 / 数据服务端 |
| 使用次数、最近时间 | 由云端账单聚合后缓存 | 服务端 |
| 进行中的使用（设备 id + 开始时间） | 本机 SP | 仅在服务端确认启动后写入；状态以服务端为准，服务端回报待机/异常时自动清除，正常结束走 `dev/end` |
| 收藏缓存 | 本机 SP（只读缓存） | 服务端（每次刷新覆盖） |

## 4. 页面设计说明

### 4.1 登录

- 顶部品牌块（品牌色圆角卡）：产品名 + 业务范围 + "全新设计 · 同一账号 · 真实服务端"。
- 表单卡：手机号 → 验证码行（输入框 + 服务端图形码 + 换一张）→ 短信码行（输入框 + 60s 倒计时按钮）→ 登录。
- 底部：真实服务端说明、协议提示、"仅预览界面（演示数据，不连接服务端）"。
- 状态：图形码加载中/失败可重试；发送中/倒计时；登录中按钮内联进度；错误内联红字。

### 4.2 首页

- 问候 + 设备统计；右上刷新。
- **进行中使用卡片**（金色系）：只有在服务端确认设备已离开待机后才会出现。状态胶囊与「服务端 HH:mm:ss」来自 `dev/status`（**每 2s 轮询**，仅前台）；没有快照时胶囊显示「同步中」而不是「使用中」。另有 `HH:mm:ss` 本机计时、查看设备/使用记录；底部提示「每 2 秒同步服务端状态 · 计费以服务端为准」并提供「结束使用」（调用服务端 `dev/end` 结算，成功后才清除本机指针）。点「结束使用」后卡片会保留到请求结束（按钮置灰 + 「正在结束…」，仅请求期间），避免卡片瞬间消失让用户以为没点到。下拉刷新与回前台都会用 `dev/status` 对账本机记录。预览模式不轮询、也不落盘。
- **扫码主卡**（品牌深青）：一句话价值 + "打开相机扫码"。
- **常用设备**横向卡片：类型标签、名称、位置/编号、状态胶囊、置顶标记。
- **最近使用**列表：类型首字图标、名称、类型·日期时间、使用次数。
- 空态：分别说明"为什么空"与"怎么产生"。

### 4.3 扫码

- 全屏相机 + 260dp 圆角取景框 + 底部半透明提示卡；右上角常驻「扫码 / 输入编号」分段。
- **手动输入编号**：切换到输入模式后，输入设备贴纸编号或二维码里的 `id`，点「查询设备」走与扫码相同的服务端解析（`qr/use`），成功直接进入设备详情；失败按原因提示。
- 识别链路状态文案：识别 → 服务端查询（显示码类型）→ 成功/失败。
- 厂商码兼容：`/q/<n>/<id>` 形状（例如饮水机面板上的 `https://i.hnkzy.com/q/1/<15位编号>`）本地按通用码取出 id；只要服务端返回了 `dev` 就进设备页，即使服务端省略 `qr.type`。
- 失败原因具体化："不是有效二维码 / 服务端未返回设备 / 该码类型暂不支持 / 网络错误"，并提供关闭/重试。
- 相机权限被拒时给出说明与「授予权限」，同时仍可切到输入模式继续使用。

### 4.4 设备详情

- **主卡**：类型标签、设备名（大字）、状态胶囊、编号、商户；运行中时显示"当前模式/更新时间"。
- **主按钮**：单一大按钮，文案随状态变化（立即使用 / 结束使用并结算 / 设备离线，暂不可用 / 已停用 / 蓝牙设备请用原应用）；请求期间按钮**置灰并显示旋转指示 + 「正在启动设备…」/「正在结束…」**，结果提示在请求完成后出现，不设固定等待时长。点「立即使用」后，对状态可观测的设备（水控/淋浴/饮水机、洗衣/烘干/洗鞋、吹风机、充电桩）客户端会等设备真正离开待机（最多约 11 秒，`dev/status`），确认后才报「已启动」并记录进行中；若设备一直是待机，则显示「启动未生效」、附服务端状态与 `dev/start` 返回的 `data`，不会留下假的「使用中」。`StartCommandLock` 仅在设备仍待机、有本设备记录且尚未见过运行态时提供最多 20s 的重复启动保护；订单结束、离开待机或本机记录消失立即解锁。
- **次操作**：收藏（服务端）、置顶（本机）、订单（跳转）。
- **模式**：Chip 组，来自 `bm.parts`，标注"费率来自服务端配置"。
- **支付方式**：Chip 组，来自 `payItems`；支付宝（21）与余额类（91/92/93）可直接使用，其余渠道标注需对应 SDK。
- **信息卡**：名称/编号（等宽字体）/类型/位置/服务单位/固件/使用说明/收藏状态。
- **余额卡**：总额 + 现金/赠送拆分。
- **自动刷新**：进入/返回/回前台即刷新；启动中/运行中每 2s 轮询（含启动成功后 20s 受限窗口），空闲与异常状态不轮询，切后台即停、回前台先补一次，界面无手动刷新按钮。

### 4.5 设备

- 搜索框（名称/编号/类型），实时过滤。
- 分栏 Chip：收藏 / 常用 / 最近。
- 类型筛选：横向滚动，单选可取消。
- 列表卡片：类型首字块、名称、副标题（类型·商户/编号）、状态、收藏标记、置顶星标。
- 空态文案区分三种分栏，并说明数据归属（服务端/本机）。

### 4.6 订单

- 分栏：使用中 / 消费记录。
- 使用中：计时卡 + 打开设备 + 刷新记录；无进行中时给空态与说明。
- 消费记录：卡片行（商品/摘要、时间、设备、金额、支付状态），点击拉取账单详情；分页"加载更多"；底部标注接口来源。
- 账单详情：底部面板（ModalBottomSheet），字段：账单号、创建/更新时间、金额、优惠、状态、设备（名称/编号/类型）、服务单位、备注、说明、商品明细。

### 4.7 我的

- 资料卡（首字母头像、名称、脱敏手机号、用户编号）。
- 指标卡：钱包 / 积分 / 收藏数；「钱包」可点击进入充值页（余额、企业、充值商品，商品由 `prd/lst type=1` 下发）。
- 服务端连接卡：接口地址、客户端标识、令牌状态、本机最近设备数、**接口连通性自检**（真实调用 `master` 展示结果）、清空本机记录。
- 关于卡：已实现能力 / 未集成能力（明确列出支付 SDK、门禁、洗衣、驾考）。
- 退出登录。

## 5. 关键交互流程

### 5.1 登录

```
启动 → 有 token? ──是→ 首页（后台刷新 master）
              └─否→ 登录页 → 取图形码(s,r) → 输入手机号+图形码
                        → POST acc/login/code → 60s 倒计时
                        → 输入短信码 → POST acc/login
                        → 保存 token/uid → 拉取 master → 首页
```

### 5.2 扫码使用（核心闭环）

```
首页/底栏扫码 → 相机识别 → QrParser 预解析(type,id)
   → GET /qr/use?id  → qr.type ∈ {3,8} 且 dev 非空；缺 qr.type 时由可用 dev 判定
   → 记录"最近使用" → 设备详情(dev/home/1?apply=6)
   → 状态=就绪 → [立即使用] → dev/start(did,ptype,args,rcp,cnt)
   → 服务端受理 → 每 2s 读 dev/status：离开待机(1/30/10/20)=已启动
                  一直 99 / 异常 / 读不到 = 启动未生效（不记录、不轮询）
   → 已确认 → 本地记录进行中 + 进入 2s 轮询
   → 状态=运行中 → [结束使用并结算] → dev/end
   → 成功 → 清除进行中 → 引导订单页 → 服务端生成账单
```

### 5.3 收藏

```
详情 [收藏] → dev/favo?did&remove=0/1 → 成功
   → 更新内存收藏表 + 写入本地缓存
   → 设备页"收藏"分栏 / 首页"常用设备"同步变化
```

### 5.4 搜索与筛选

```
设备页 → 输入关键字 → 同时匹配 名称 / 编号 / 类型名
      → 叠加类型 Chip → 结果即时更新
      → 空结果给出"没有匹配的设备"
```

## 6. 视觉系统

### 6.1 品牌与色板

| 角色 | 日间 | 深色 |
|---|---|---|
| Primary（品牌深青） | `#0B6E6A` | `#7DE2D1` |
| Primary Container | `#A6F2E2` | `#00504A` |
| Secondary（水蓝） | `#2C7A8C` | `#90D3E4` |
| Tertiary（暖金，用于进行中/置顶） | `#6F5B2E` | `#E4C98A` |
| Background | `#F5F7F6` | `#121716` |
| Surface | `#FFFFFF` | `#1B2221` |
| Error | `#BA1A1A` | `#FFB4AB` |

状态色（胶囊）：在线=水蓝底、运行中=暖金底、启动中=品牌浅底、离线=中性灰、禁用/故障=错误红。

首页「扫码即刻使用」卡片使用主题 `primary/onPrimary`（不再写死品牌色），Android 12+ 打开「动态取色」后会跟随壁纸配色。

### 6.2 字体与排版

- 系统默认字体（中文最优），标题 SemiBold/Bold，正文 14–16sp，行高 22–24sp。
- 设备编号等长串使用等宽字体展示。
- 数字（金额/时长）用 `headlineSmall` 提升可读性。

### 6.3 形状与间距

- 卡片圆角 16–24dp，输入框 16dp，按钮 14–16dp，胶囊 50%。
- 基础间距 8dp 栅格；页面横向 16dp；卡片内 14–20dp。

### 6.4 组件

- 底部导航（Expressive）：4 项 + 中央 54dp 扫码按钮；选中项为药丸高亮 + 图标 1.10 倍弹性缩放 + 颜色渐变，未选中项 86% 透明度。
- 加载：自绘波浪线/波浪环（正弦相位 + 旋转挤压），替代默认转圈。
- 按压反馈：卡片/按钮按下 spring 缩放 0.965，松开回弹。
- 页面切换：淡入 + 0.985 缩放，200ms 左右。
- 状态胶囊、指标块、信息行、空态、错误态、提示条、设备卡、账单行、底部详情面板。

### 6.5 深色模式

- 颜色走 `MaterialTheme.colorScheme`；主卡使用 `primary/onPrimary`，卡片使用主题容器色。
- 状态栏/导航栏透明 + 图标深浅随主题切换。
- 「我的 → 外观」提供 **跟随系统 / 浅色 / 深色** 三档，选择持久化在 `Store`（安装级偏好，
  退出登录不清除）。
- 动态配色（Android 12+ Material You）在同一张卡片里提供开关，默认关闭以保持品牌一致；
  Android 12 以下隐藏动态取色开关。

### 6.6 卡片过渡与返回手势

- 首页、设备、订单、我的属于同级页面，切换及回首页不做空间位移，背景页与底栏保持原位。
- 使用 [Google Compose 共享元素 API](https://developer.android.com/develop/ui/compose/animation/shared-elements)：根 `SharedTransitionLayout` 配合 NavHost 的 `AnimatedVisibilityScope`，卡片与对应全屏页通过 `sharedBounds` 展开/收回；设备文字随容器统一缩放，钱包金额保留独立共享元素。容器圆角随卡片/全屏状态变化，加载与错误页也在同一容器内。
- 设备入口覆盖首页收藏、最近、进行中卡片，设备列表和订单进行中卡片；扫码页对应首页扫码卡或底部扫码按钮，手输页对应相机右上角入口，钱包页对应「我的」钱包区域。匹配键包含来源导航条目、入口区域、设备 id 及内容部分，避免同一设备多处出现时串卡。
- 预测性返回由 NavHost 寻帧，取消恢复当前页，完成收回原入口；来源被移除或未参与布局时退化为淡变。扫描/手输解析成功会移除扫描栈，设备详情没有卡片来源，此时使用 [官方全屏返回示例](https://developer.android.com/develop/ui/compose/system/predictive-back-setup) 的 100%→90% 返回预览、110%→100% 打开并淡入。
- 容器与导航过渡使用 Compose 默认动画规格和系统 Animator 倍率，不指定自定义曲线或毫秒数；未匹配的卡片不附加圆角动画。保留现有 Compose 1.9.2 / Navigation 2.9.6，仅在共享过渡封装与根布局显式使用 `ExperimentalSharedTransitionApi`，不升级依赖。
- 圆角在绘制阶段读取动画值，复用裁剪路径；设备详情从 VM 的账号内存状态同步读取名称、类型、编号作为首屏，不读盘或增加另一套缓存。进场时仅显示身份信息和静态占位，不创建波浪加载动画、钱包、模式与业务按钮；无已知信息时先显示编号和通用标题。缓存不能授权启停或支付。
- 详情请求与进场并行，完整成功/失败内容在导航及共享过渡稳定后显示；失败保留已知身份和重试。离开页面取消等待，无固定延时。设备页仅使用共享容器本身的淡变，避免 NavHost 再叠整页 alpha；无卡片来源仍保留原 fade+scale。
- 导航刷新等待目标条目进入 RESUMED 且共享过渡结束，再沿用 `bumpRefresh()` 的 200ms 合并，避免导航开始时同时刷新退场列表；后续详情刷新响应也等待正在进行的过渡稳定后发布。
- 主页面和底栏同属一个目的地；共享层只在应用内容边界裁剪，避免被列表卡片裁切，也不覆盖状态区/演示横幅。相机使用 TextureView 参与变换与裁剪。
- 账单详情、外观等 Material Sheet 保留面板进出；充值商品、启停等操作不转换成全屏卡片。根页退回桌面由系统负责，Android 13 以下只能验普通返回；真机帧率、厂商差异与窗口动画仍需实机验收。
