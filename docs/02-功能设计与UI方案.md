# 功能设计与 UI/UX 方案

> 配套文档：[`01-逆向分析报告.md`](01-逆向分析报告.md)、[`03-技术方案与开发计划.md`](03-技术方案与开发计划.md)
> 设计原则：**业务能力对齐原服务端，页面结构、交互与视觉完全重做**，不复刻原应用布局。

## 客户端更新

登录页「检查客户端更新」位于登录卡片下方，与表单一起滚动，不覆盖登录按钮；页面避让系统栏和软键盘。登录请求期间显示「登录中…」并防重复点击，失败在按钮上方及 Snackbar 提示，缺少账号或令牌不进入首页，成功进入首页并提示「登录成功」。登录页更新入口和「我的 → 关于本客户端 → 检查更新」为手动入口；启动／回到前台及前台运行期间每 5 分钟自动检查（5 分钟合并）。新发布策略包含历史日志，弹窗按版本从新到旧展示当前安装之后至目标版本的全部已有条目；不包含当前及更旧版本。旧策略或损坏历史回退最新说明并提示未提供跨版本日志。普通更新可稍后；强制更新阻止进入业务页面，返回键退出整个应用，下载随 VM 任务结束取消。重新打开仍受限，点击外部和登出不解除策略。点击「立即更新」在应用内从本次确认的来源下载 APK；下载状态固定在弹窗底部操作按钮上方，使用醒目底色、全宽加粗进度条与百分比，不随版本日志滚动；同一区域显示失败、重试及安装提示，下载可取消；验证通过后使用目标版本专属文件和 URI 打开系统安装器，首次引导未知来源授权。用户取消安装后保留「安装新版」入口；只有实际安装达标版本才解除限制。断网保留已知策略，无有效策略不误拦截。发布控制与限制见 [docs/06](06-工程规范与路线图.md#github-更新发布)。

## 1. 设计目标

1. **重扫码、轻导航**：把"扫码 → 看设备 → 开始使用"压缩到 2 次点击内；扫码按钮常驻底部导航中央。
2. **状态可信**：所有设备状态、余额、账单都显示服务端返回值与更新时间，本地只做"索引与偏好"。
3. **一眼判断**：设备卡片/详情用统一状态色（在线/运行中/离线/禁用）与主按钮（立即使用/结束并结算）。
4. **弱网可读**：加载、空数据、网络异常、设备不可用、令牌过期都有明确页面态与可执行动作。
5. **Material 3 Expressive**：官方增强组件、相邻按钮挤压回弹、色调分层与清晰留白，日间/深色自动跟随系统。

## 2. 功能清单

### 应用图标

图标采用深海蓝 `#2457A7` 底色，主体为冰白与浅冰蓝的「流动水滴」：两段连续曲面以 S 形波纹留白连接，使用克制的玻璃/珠光高光，强调水、流动与现代感。无文字、屋檐或官方标志。主体保持大轮廓，避免小尺寸细节堆叠。

使用 imagegen 内置工具生成，[图标预览](../artwork/app-icon.png)、[原始透明前景](../artwork/app-icon-foreground.png)与[最终提示词及导出说明](../artwork/app-icon.prompt.txt)保留供后续维护。原始前景不修改；Android 导出按有效透明边界等比缩放并居中，背景颜色由原生资源精确指定。

Manifest 使用 `@mipmap/ic_launcher`；API 24/25 提供 48/72/96/144/192px 五档 PNG。API 26+ 使用独立天蓝背景与 432px 透明前景，主体最长边为 60dp，居于中央 66dp 安全区。API 33+ 单色资源由同一前景的 alpha 导出白色轮廓，保持水滴和波纹留白一致。圆形与圆角方形由系统 mask 裁切，资源不预先画圆角。

### 2.1 保留（对接原服务端）

| 功能 | 服务端能力 | 新客户端实现 |
|---|---|---|
| 手机号登录 | 图形码 + 短信 + `token` | 完整实现（图形码直接取服务端图片） |
| 自动登录 / 令牌失效 | `Authorization` + `code=-99` | 启动恢复令牌；`-99` 自动登出并提示 |
| 昵称与网络头像 | `acc/upt`、`master.account.img` | 「我的」修改昵称，保存成功后显示；HTTPS 头像加载后直接显示，滚动返回保留位图，失败保留首字占位 |
| 使用积分 | `acc/upt {useScore:0/1}` | 设备详情开关，保存成功后更新；账号服务端记住选择，启动与保存互斥；可用积分显示 `mission-lst.accScoreRsp.validScore`；缺省偏好视为关闭，可设置 |
| 自动 / 手动签到 | `acc/score/mission-lst`、`acc/score/score-send` | 自动默认开启，「我的」可关闭；首次进入刷新状态，未签可手动签到、已签禁用按钮；首页也显示结果提示。先读状态、提交后严格确认；缺积分账号/daily/week 采用原版零缺省，非法位图或缺时间/奖励不提交。自动不重发当天不明结果，手动先查再明确重试，忙碌共用防重 |
| 扫码识别 | `qr/use` | CameraX + ML Kit 扫码，本地预解析后交服务端确认 |
| 设备详情 | `dev/home/1` | 重绘为信息卡 + 状态区 + 操作区 |
| 设备实时状态 | `dev/status` 轮询 | 2s（启动中/运行中，含启动成功后 20s 受限窗口）；普通空闲/异常不轮询；占用受阻时读取完整详情，仅前台运行，显示"更新时间" |
| 启动设备 | `dev/start` | 主按钮 + 支付方式选择 + 模式选择 |
| 结束并结算 | `dev/end` → `dev/status` | 受理后继续显示「正在结束」，同设备确认待机后切换「立即使用」；账单以服务端结算为准 |
| 切换模式 | `dev/mode/start` | 模式 Chip 组 |
| 收藏 / 取消 | `dev/favo`、`master.favos` | 详情页收藏按钮 + 设备页收藏分栏，双端一致 |
| 消费记录 / 账单详情 | `bill/lst-owner`、`bill/view-full` | 订单页"消费记录"分栏 + 底部详情面板 |
| 扫码失败兜底 | `qr/use` | **手动输入编号**（与扫码同一解析链路） |
| 账单支付（支付宝） | `bill/pay/channels`、`trans/prepay`、`trans/confirm` | 未付款账单详情底部固定「去支付」（打开即见）→ 官方 Alipay SDK → 服务端确认 |
| 自动刷新 | — | 打开应用/切页/返回按页面刷新；我的同一前台周期复用资料，首次进入、回前台、跨服务端日期及下拉时刷新，界面无刷新按钮 |
| 账号资料 | `master.account` | 我的页资料卡、欠费；积分另读 mission-lst |
| 钱包余额与充值 | `acc/wallet/owner`（`data.aw`）、`prd/lst?type=1`、`bill/save` | 我的→钱包→服务端充值商品→创建账单→支付 |
| 微信支付 | 暂不支持 | 不展示充值支付渠道，不接入 SDK |
| 支付宝免密签约 | `ui/app/sign-pga?type=20` | 优先 sign + SDK；不将协议渠道集合作为用户签约状态 |

### 2.2 新增（本地实现，关联真实设备）

| 功能 | 数据来源 | 说明 |
|---|---|---|
| 常用设备 | 收藏 ∪ 使用次数≥2 的设备，按"置顶 → 最近使用 → 使用次数"排序 | 次数来自云端账单聚合，置顶保存本机 |
| 最近使用 | `bill/lst-owner` 的 `dev` 聚合（服务端历史）+ 仅扫码未使用的本地记录 | 最多 60 条，单条可清除 |
| 设备搜索 | 名称 / 编号 / 类型 | 本地过滤，点击后打开真实详情 |
| 类型筛选 | 设备类型枚举 | 横向 Chip 组 |
| 启动页面 | 我的 → 启动页面 | 首页 / 设备页，默认首页；保存本机，登出保留 |
| 统一异常反馈 | 网络、`-99`、`-87/-88/-52` 等 | Snackbar + 内联错误卡 |
| 深色模式 | 系统 | 全套色板与状态色适配 |

### 2.3 明确不做

- 云闪付、银行和微信 SDK 支付均未接入
- 门禁蓝牙开门、IC 卡读写、门禁 NFC、考勤打卡
- E 袋洗、驾考、积分商城、广告位
- 任何形式的"模拟开机/模拟计费"

### 2.4 本地数据与服务器数据边界

| 数据 | 存放 | 权威方 |
|---|---|---|
| 账号、收藏、设备状态、余额、账单、订单 | 服务端 | 服务端 |
| 令牌、手机号 | 本机 SP | 服务端签发 |
| 最近设备索引、置顶 | 本机 SP（JSON） | 索引本机 / 数据服务端 |
| 最近索引的次数、时间 | 云端近期账单聚合与本机已确认启动/扫码索引合并 | 仅本机排序依据，不代表全部计费次数或账单状态 |
| 进行中的使用（设备 id + 开始时间） | 本机 SP | 仅在服务端确认启动后写入；命令受理但状态未知时另存待确认书签，首页只显示「启动待确认」；状态以服务端为准，待机/异常清除，正常结束走 `dev/end` |
| 收藏缓存 | 本机 SP（只读缓存） | 服务端（每次刷新覆盖） |

## 3. 信息架构

已登录时，冷启动按「我的 → 启动页面」选择首页或设备页；未登录仍先显示登录，登录后进入所选页。修改偏好不立即跳页，返回前台、系统重建和返回详情保留当前导航栈；下次重新启动主界面时生效。底部四项导航、扫码入口和详情返回共用同一导航规则，两种启动页均可使用。

## 4. 页面设计说明

### 4.1 登录

- 顶部品牌块（品牌色圆角卡）：产品名 + 业务范围 + "全新设计 · 同一账号 · 真实服务端"。
- 表单卡：手机号 → 验证码行（输入框 + 服务端图形码 + 换一张）→ 短信码行（输入框 + 60s 倒计时按钮）→ 登录。
- 状态：图形码加载中/失败可重试；发送中/倒计时；登录中按钮内联进度；错误内联红字。

### 4.2 首页

- 问候 + 最近同步时间；支持下拉刷新。
- **进行中使用卡片**（主题 tertiary 色）：受理后先显示「启动待确认」，不显示用时或声称运行；确认后显示服务端状态、更新时间与本机用时。查看设备、使用记录与结束入口始终可达。结束期间保持卡片和「正在结束…」；未确认则提示并保留查询入口。返回首页与重建恢复、轮询及并发规则见 [启动确认与对账](03-技术方案与开发计划.md#31-全自动刷新无手动刷新按钮)。

- **扫码主卡**（品牌深青）：一句话价值 + "打开相机扫码"。
- **常用设备**横向卡片：类型标签、名称、位置/编号、状态胶囊、置顶标记。
- **最近使用**列表：类型首字图标、名称、类型·日期时间、使用次数。
- 空态：分别说明"为什么空"与"怎么产生"。

### 4.3 扫码

- 全屏相机 + 圆角取景框 + 底部提示卡；右上角单独「手动输入」按钮进入独立页面。
- **手动输入编号**：进入独立输入页后，输入设备贴纸编号或二维码里的 `id`，点「查询设备」走与扫码相同的服务端解析（`qr/use`），成功直接进入设备详情；失败按原因提示。
- 识别链路状态文案：识别 → 服务端查询（显示码类型）→ 成功/失败。
- 厂商码兼容：`/q/<n>/<id>` 形状（例如饮水机面板上的 `https://i.hnkzy.com/q/1/<15位编号>`）本地按通用码取出 id；只要服务端返回了 `dev` 就进设备页，即使服务端省略 `qr.type`。
- 失败原因具体化："不是有效二维码 / 服务端未返回设备 / 该码类型暂不支持 / 网络错误"，并提供关闭/重试。
- 相机权限被拒时给出说明与「授予权限」，同时仍可进入手动输入页继续使用。

### 4.4 设备详情

- **主卡**：类型标签、设备名（大字）、状态胶囊、编号、商户；运行中时显示"当前模式/更新时间"。
- **主按钮**：随状态与占用身份显示立即使用、本账号结束使用并结算、他人/未知占用禁用提示、离线、停用或蓝牙提示。忙碌时置灰并显示进度；受理、启动确认与结束确认分别表述，未知结果引导刷新，不提前显示成功。状态变化及时解锁，不加固定冷却；确认规则和 `StartCommandLock` 边界统一见 [docs/03](03-技术方案与开发计划.md#31-全自动刷新无手动刷新按钮)。

- **次操作**：收藏（服务端）、置顶（本机）、订单（跳转）。
- **模式**：Chip 组，来自 `bm.parts`，标注"费率来自服务端配置"。
- **支付方式**：Chip 组，来自 `payItems`；支付宝（21）、余额类（91/92/93）及微信（11）按共用渠道能力选择；未集成渠道明确提示，微信实付另受开放平台配置约束。
- **信息卡**：名称/编号（等宽字体）/类型/位置/服务单位/固件/使用说明/收藏状态。
- **余额卡**：总额 + 现金/赠送拆分。
- **自动刷新**：进入/返回/回前台即刷新；启动中/运行中每 2s 轮询（含启动成功后 20s 受限窗口），普通空闲与异常状态不轮询，占用受阻时读取完整详情直至释放，切后台即停、回前台先补一次，界面无手动刷新按钮。

结束确认后直接展示同设备待机快照，旧详情不能让按钮回退；实现规则见 [docs/03](03-技术方案与开发计划.md#31-全自动刷新无手动刷新按钮)，验证证据见 [docs/05](05-真实支付与计费实测.md#9-工程验证记录)。

### 4.5 设备

- 搜索框（名称/编号/类型），实时过滤。
- 分栏 Chip：收藏 / 常用 / 最近。
- 类型筛选：横向滚动，单选可取消。
- 列表卡片：类型首字块、名称、副标题（类型·商户/编号）、状态、收藏标记、置顶星标。
- 空态文案区分三种分栏，并说明数据归属（服务端/本机）。

### 4.6 订单

- 分栏：使用中 / 消费记录；主分栏使用深蓝实心选中态，账单筛选使用小一级文字、透明未选中态与浅色选中态；两层使用官方 ButtonGroup，全部可见时按下联动相邻按钮；窄屏或大字放不下的项进入「更多选项」，此时保留官方形变并停用宽度扩张，避免遮挡更多入口。
- 使用中：计时卡 + 打开设备 + 刷新记录；无进行中时给空态与说明。
- 消费记录：卡片行（商品/摘要、时间、设备、金额、支付状态），点击拉取账单详情；首页与待付角标均覆盖最近 50 条账单（含充值单），更早记录通过分页“加载更多”查看；角标不是全部历史待付款总数。
- 账单详情：底部面板（ModalBottomSheet），视口按当前窗口高度确定并保持底部对齐；安全区计入视口内部，不用当前偏移或可滚动内容反推高度。固定标题、金额/状态和底部操作；未付账单的「取消订单」在左、「去支付」在右，等宽等高、最小 56dp，文字变大时共同增高，仅明细区域滚动；已支付账单不显示付款入口。字段包括账单号、创建/更新时间、优惠、状态、设备、服务单位、备注、说明和商品明细，长商品名称允许换行。
- 快速点击账单只保留一次详情读取；详情缺少 bill 对象时沿用列表行。关闭按钮、返回和下滑可退出；详情先完成收起再打开支付面板，避免两个遮罩叠加。
- 支付面板沿用稳定视口，标题、金额和确认按钮固定，渠道/说明可滚动。读取渠道失败时底部操作变为「重试」，小屏大字也无需滚到说明末尾才能重试；付款期间禁止切换渠道、滑动/返回/外部关闭，保留入口防重和 finally 解锁，不自动重试支付。

### 4.7 我的

- 资料卡（网络头像、名称、脱敏手机号、用户编号；失败回退首字）。
- 启动页面设置：首页 / 设备页，默认首页；安装级保留，修改不跳页，下一次重新启动主界面生效。启动页面与外观各用独立圆角卡片，标题配主题色图标，保持与设备卡片一致的留白与层级。
- 选择项使用等宽圆角块，图标与文字作为整体水平、垂直居中；选中时仅改变背景色，不附加勾选、描边或加粗；整块可点击并提供单选语义。启动页面卡片不显示未登录说明，选项文本按宽度换行，动态取色放入外观卡片的独立浅色调区域。启动页、主题和动态取色保存到安装偏好。
- 指标卡：钱包 / 积分 / 收藏数采用三个等宽列，列间距 8dp，标签与数值居中；钱包整列保留点击与共享过渡。金额长度不改变三列的宽度分配；数值保持单行，并在 14–24sp 范围内按空间缩放，避免窄屏或大字体将货币符号挤到单独一行；极长数值在最小字号仍放不下时明确显示省略号，钱包详情提供完整余额。「钱包」可点击进入充值页（余额、企业、充值商品，商品由 `prd/lst type=1` 下发）。
- 使用指南入口位于关于客户端卡。
- 关于卡显示客户端简介、版本与更新设置。
- 关于版本行连续点击七次启用安装级“开发者工具”入口；开发者工具为独立列表页，当前提供“NFC 采集”子页，后续工具可各自增加入口，不与采集内容混放。
- NFC 子页显式开始/停止，仅读取系统缓存的原始 NDEF，不打开链接或执行设备操作。支持查看本机记录、清空与主动导出原始数据；后台、锁屏、返回工具列表立即停止，返回后需重新开始。单条完整消息最多 64KiB、日志最多 128KiB；页面截取末尾显示时明确提示可导出完整内容。实际卡片自动设备路由仍待独立验收。
- 退出登录。

## 5. 关键交互流程

### 5.1 登录

```
启动 → 有 token? ──是→ 所选启动页（首页 / 设备页，后台刷新）
              └─否→ 登录页 → 取图形码(s,r) → 输入手机号+图形码
                        → POST acc/login/code → 60s 倒计时
                        → 输入短信码 → POST acc/login
                        → 保存 token/uid → 拉取 master → 所选启动页
```

### 5.2 扫码使用（核心闭环）

```
首页/底栏扫码 → 相机识别 → QrParser 预解析(type,id)
   → GET /qr/use?id  → qr.type ∈ {3,8} 且 dev 非空；缺 qr.type 时由可用 dev 判定
   → 记录"最近使用" → 设备详情(dev/home/1?apply=6)
   → 状态=就绪 → [立即使用] → dev/start(did,ptype,args,rcp,cnt)
   → 服务端受理 → 每 2s 读 dev/status：离开待机(1/30/10/20)=已启动
                  待机 / 异常 = 未确认启动并清待确认；读不到 = 保留待确认入口
   → 已受理 → 待确认书签（首页查询入口）
   → 已确认 → 本地记录进行中 + 进入 2s 轮询；状态未知保留待确认，待机/异常清除
   → 状态=运行中且可确认本账号占用 → [结束使用并结算] → dev/end
   → 同设备确认待机 → 清除进行中 → 订单页核对服务端账单
```

### 5.3 收藏

```
详情 [收藏] → dev/favo?did&remove=0/1 → 成功
   → 更新内存收藏表 + 写入本地缓存
   → 设备页"收藏"分栏 / 首页"常用设备"同步变化
```

### 5.4 搜索与筛选

```
设备页 → 输入关键字 → 同时匹配 名称 / 编号 / 类型名
      → 叠加类型 Chip → 结果即时更新
      → 空结果给出"没有匹配的设备"
```

### 5.5 NFC 设备入口

登录后的普通页面在前台接收 NFC 卡片，开发者 NFC 采集子页独占读取模式。已核实的官方 HTTPS `nfc.html?q=…` 链接先交服务端 `qr/use` 解析，只在返回真实设备时进入详情。本次经前台 reader callback 确认，或后台 Intent 的 Tag 通过当前 NFC 服务活体读取确认后，会在最新完整详情到达、页面 RESUMED 且进场结束后自动尝试一次「立即使用」。复用现有支付方式选择、模式参数、启动互斥与服务端状态确认，不自动签约或代替用户操作支付 SDK。普通网页链接、手工添加 autoStart 参数、无 Tag/伪造/已离场 Tag 仅打开详情。系统交付的同类 NDEF/VIEW Intent 同样验证域名和路径；冷启动需完成登录并处于可用前台，已消费 Intent 不在 Activity 重建时重放。离开前台取消待完成的 NFC 导航和自动开始凭据。自动开始凭据只在当前 VM 内存中保留，领取后立即消费，导航恢复不能生成凭据；失败不重试，运行中设备不自动结束。新的同设备碰卡也须等待本次完整详情，不以旧页快照自动执行。NFC 采集子页拦截系统路由，只提示先开启采集，不查询或启动设备。

当前实物卡的支付宝 `t` 短码仍缺有效的平台设备路由；识别到此格式会说明中转尚未适配，不打开任意卡片链接、不把 appId/短码当设备编号。后台碰卡的分发由系统及卡片 AAR 决定，不能保证取代支付宝默认入口。[Android 16 起网页型卡片改用 ACTION_VIEW](https://developer.android.com/develop/connectivity/nfc/nfc)，因此同时注册精确路径的 VIEW 入口；本项目没有官方域名控制权，不声明已验证 App Links，后台打开仍受系统默认链接设置限制，前台 reader mode 不依赖该默认设置。

## 6. 视觉系统

### 6.1 品牌与色板

浅色主题以用户提供的完整参考图为标准：`#0055D6` 主蓝/白字、`#F9F8FE` 页面、`#E5E7F4` 卡片、灰紫次级容器、灰蓝状态容器与黑底浅字提示条。全应用直接使用同一份完整 `ColorScheme`，保留 primary、secondary、tertiary、surface 和 inverseSurface 的分工。首页、设备、订单、钱包、我的、详情、登录及账单/支付面板共用这些角色；不再将次级色强制复制成主蓝，也没有首页独立的猜色文字规则。深色独立使用协调的浅蓝、蓝灰与中性深色。

- 正文与实际背景以对比度至少 4.5:1 为回归目标；包括扫码水波、卡片、状态标签、提示条、主要和次级容器。

- 底栏沿用页面背景、关闭色调抬升；启动背景随浅深色主题。桌面图标保留既有深海蓝水滴资产。

### 6.2 字体与排版

- 系统默认字体（中文最优），标题 SemiBold/Bold，正文 14–16sp，行高 22–24sp。
- 设备编号等长串使用等宽字体展示。
- 数字（金额/时长）用 `headlineSmall` 提升可读性。

### 6.3 形状与间距

- 卡片圆角 16–24dp，输入框 16dp，按钮 14–16dp，胶囊 50%。
- 页面横向与卡片内边距统一 16dp，页面卡片间距 12dp；主操作最小高度 56dp，大字体允许自然增高。账单详情左右按钮等宽等高。

### 6.4 组件

- 底部导航（Expressive）：4 项 + 中央 54dp 官方增强扫码按钮；选中项为药丸高亮 + 图标 1.08 倍弹性缩放 + 颜色渐变，未选中项使用 onSurfaceVariant。待付角标放在图标槽内，不越过药丸裁剪边界，保持大字体下数字完整与各项图标/文字基线一致。
- 主题采用官方 `MaterialExpressiveTheme` 与 `MotionScheme.expressive()`；主按钮、文字和图标按钮使用官方按压形变。设备/订单分栏、筛选、设备类型、模式和渠道使用带自动溢出的 `ButtonGroup`；全部可见时按压扩张 25%，相邻按钮随之让位并回弹，溢出时停用宽度扩张以免覆盖「更多」，保留官方按钮形变。启动页与外观使用共享交互源的官方宽度动效，保持仅背景选中和单选语义，大字选项自然换行并垂直居中。扫码使用增强 `FilledIconButton`。刷新指示器使用 `surfaceContainerHigh` 中性底与 `primary` 图形，保留官方下拉与形变加载，浅色、深色及动态取色共用主题语义色。设备/订单第一行分栏使用实心主色选中，第二行类型/账单筛选使用低强调色调与较小文字，未选中项也使用 surfaceContainerHighest 背景与 outlineVariant 边界；统一选择按钮的基础与选中圆角为 14dp，按压仍使用官方形变。按钮、选择与加载沿用系统动画倍率，无额外固定操作锁。
- 加载：页面使用 `ContainedLoadingIndicator`，按钮内使用 `LoadingIndicator`，下拉刷新使用固定组合的官方轻量 `PullToRefreshDefaults.Indicator`，避免手势首帧创建复杂形变组件；拉动距离、松手和刷新沿用同一个手势状态。长任务与更新下载使用 `LinearWavyProgressIndicator`；下载仍显示真实字节百分比，未确定进度不伪装为确定进度。删除旧自绘波浪实现。
- 首页扫码主卡与中央扫码按钮使用同一组高亮主题配对；主卡使用水波纹背景、titleLarge 标题、bodyMedium 正文与 24dp 留白，内部提示按钮使用浅色表面；空态使用色调图标容器，设备卡统一主题圆角。静态装饰不引入持续动画。
- 按压反馈由增强组件的形状与主题动效驱动；共享卡片与页面切换规则见下节，不为按钮再叠统一缩放或固定时长。
- 状态胶囊、指标块、信息行、空态、错误态、提示条、设备卡、账单行、底部详情面板。

### 6.5 深色模式

- 颜色走 `MaterialTheme.colorScheme`；扫码主卡使用 `scanCardColors()` 返回的当前 `primary/onPrimary` 配对，卡片使用主题容器色。
- 状态栏/导航栏透明 + 图标深浅随主题切换。
- 「我的 → 外观」提供 **跟随系统 / 浅色 / 深色** 三档，选择持久化在 `Store`（安装级偏好，
  退出登录不清除）。
- 动态配色（Android 12+ Material You）在同一张卡片里提供开关，默认关闭以保持品牌一致；
  Android 12 以下隐藏动态取色开关。

### 6.6 卡片过渡与返回手势

- 首页、设备、订单、我的属于同级页面，切换及回首页不做空间位移。详情覆盖时仅保留当前一个主页面实体及其滚动、筛选状态，返回后直接接收首个触摸，不等列表重建；设备详情打开期间，保留的来源页使用详情导航过渡的反向可见性。详情与来源在同一过渡内切换，完全展开后普通返回和预测性返回均沿原共享边界缩回设备卡片。同级页失活时隔离触摸和无障碍语义、暂停刷新并收起独立弹窗，导航前释放来源焦点和键盘；不提前整页裁剪。全屏详情失活后立即裁空本地图层以释放触摸；共享过渡激活前用页面覆盖层衔接绘制，随后交给共享边界，避免导航条目切换时交接空帧。
- 使用 [Google Compose 共享元素 API](https://developer.android.com/develop/ui/compose/animation/shared-elements)：根 `SharedTransitionLayout` 配合 NavHost 的 `AnimatedVisibilityScope`，卡片与对应全屏页通过 `sharedBounds` 展开/收回。页面采用 `ResizeMode.scaleToBounds(ContentScale.FillWidth, Alignment.TopStart)`，按最终视口测量并复用共享容器框架已有的绘制层，动画只变换和裁剪图层，不将逐帧尺寸约束传给内容重排。钱包 TITLE 键仍通过共享文字 bounds 缩放，AMOUNT 保留独立 `sharedElement`。容器圆角随卡片/全屏状态变化，加载与错误页也在同一容器内。
- 设备入口覆盖首页收藏、最近、进行中卡片，设备列表和订单进行中卡片；扫码页对应首页扫码卡或底部扫码按钮，手输页对应相机右上角入口，钱包页对应「我的」钱包区域。匹配键包含来源导航条目、入口区域、设备 id 及内容部分，避免同一设备多处出现时串卡。详情来源的点击区域位于共享变形外层，保持列表占位处可点；离开当前导航条目的页面清除无障碍语义；本地图层裁空与绘制分离：交接前用页面覆盖层保留像素，交接后由共享覆盖层绘制，触摸立即释放；保留框架返回处理，共享卡片仍在覆盖层绘制，连续重开仍核对来源条目。
- 预测性返回由 NavHost 寻帧（不再以普通 BackHandler 抢占过渡期间的返回），取消恢复当前页，完成收回原入口；来源被移除或未参与布局时退化为淡变。扫描/手输解析成功会移除扫描栈，设备详情没有卡片来源，此时使用 [官方全屏返回示例](https://developer.android.com/develop/ui/compose/system/predictive-back-setup) 的 100%→90% 返回预览、110%→100% 打开并淡入。
- 容器与导航过渡使用 Compose 默认动画规格和系统 Animator 倍率，不指定自定义曲线或毫秒数；未匹配的卡片不附加圆角动画。共享过渡使用 Compose 1.10.6 稳定 API，移除旧实验注解；Navigation 保留 2.9.6。版本与坐标跟踪优化依据见 docs/03。
- 圆角在绘制阶段读取动画值，复用裁剪路径；设备详情从 VM 账号内存状态读取名称、类型、编号作为首屏，不读盘或增加另一套缓存。主卡预先组合操作区、模式/更新时间行和模式选择骨架并保持禁用，完整响应到达后只填入内容与可用状态，减少飞入中首次创建复杂控件的峰值；等待时不展示缓存模式名称或允许选择，缓存不能授权启停或支付。详情各区使用稳定 LazyColumn key，减少加载区移除后其他区的组合槽位变动。
- 详情页创建即请求，与进场并行；成功/失败响应立即发布，可在飞入过程中渲染。加载期间导航/前台刷新信号合并，不取消重启当前请求；后续刷新继续有效，失败保留已知身份和重试。离开页面取消页面任务，无固定延时。设备页仅使用共享容器本身的淡变，避免 NavHost 再叠整页 alpha；无卡片来源仍保留原 fade+scale。
- 导航刷新仍等待目标条目 RESUMED 且共享过渡结束，再沿用 `bumpRefresh()` 的 200ms 合并，避免同时刷新退场列表；它不阻挡已经返回的详情数据。启停和扫码自动启动仍等待入场稳定，数据渲染与业务执行门槛分开。
- 主页面和底栏同属一个目的地；共享层只在应用内容边界裁剪，避免被列表卡片裁切，也不覆盖状态区。相机使用 TextureView 参与变换与裁剪。
- 账单详情、外观等 Material Sheet 保留面板进出；充值商品、启停等操作不转换成全屏卡片。根页退回桌面由系统负责，Android 13 以下只能验普通返回；真机帧率、厂商差异与窗口动画仍需实机验收。

### 个人资料、积分与签到刷新

自动签到仅在没有当日已确认缓存时检查；服务端确认后按服务端时间快照与本机经过时间缓存到当日结束，重启同日不再自动查询、提交或重复提示，跨日或本机时间回拨重新检查。自动提示按账号和服务端日期持久去重，手动签到仍实时查询并反馈；登出/换号清除缓存。

「我的」首次进入、返回前台、跨服务端日期及下拉刷新时查询 `mission-lst`，即使自动签到关闭也读取可用积分与今日签到状态，不触发写入。同一账号、前台周期与服务端日期内切换底栏、返回钱包以及导航延迟刷新信号复用已加载结果，避免页面初次组合与导航 tick 重复请求。下拉刷新等待资料、钱包与签到状态读取结束；重叠刷新合并为同一任务，账号变化取消旧任务。可用积分显示 `accScoreRsp.validScore`；查询失败显示未知，不能使用平台兑换参数充当余额。明确未签到才启用「签到」，已签到显示「已签到」并禁用；读取中或状态未知禁用按钮。提交后无论成功或拒绝均读回状态，以当日已签位确认结果，不自动重发写入。我的页为有限的固定设置块，使用保留滚动位置的连续滚动容器，使设置按钮组与自适应指标文字不再在滚动边界反复销毁、组合和测量；指标去除固有高度的重复测量。头像位图在 VM 中仅保留当前账号、URL 对应的一张小图，滚动返回或切页重挂首帧直接使用缓存；更换账号或 URL 不匹配不能复用旧位图，旧会话响应不能填充新账号缓存。实际帧率仍以真机采样为准。

设备「使用积分」缺省值按原版关闭处理，允许切换；只在服务端保存成功后更新本地状态。非法值仍保留未知，不伪造余额、抵扣或结算结果。

### 设备占用与详情滚动

详情按 `DeviceDetailData.user.id` 核对当前账号。他人占用时显示「他人使用中，暂不可用」及等待提示，不显示可执行的开始/结束按钮；运行中无使用者且无本机记录时提示暂无法确认使用者。明确属于本账号才可结束；空闲设备可开始。发出命令前再次查询完整详情，占用变化会刷新界面并保留原因。占用被阻止时前台持续读取完整详情，释放后恢复按钮；失败不自动重发命令。详情列表保持同一个可保存的标准 LazyListState，使用框架默认预取；取消额外的一屏前向/回滚缓存与入场后的状态替换，避免预取复杂控件增加主线程负担。进场数据仍即时展示，手势与滚动位置不随入场完成重建。

支付宝 NFC 长格式若内含已核对的慧生活小程序 `2019061465519660`、`devview/view?id=数字编号`，可读取服务端同编号设备后进入详情；允许其作为 NFC `codeContent` 嵌套内容。此路径不等于已支持只有 `t` 的支付宝中转卡；普通网页/显式 Intent 不授予自动启动凭据，也不新增覆盖支付宝通用链接的系统过滤器。

当前交付不再提供演示模式。历史演示截图仅用于追溯旧版布局；离线测试在独立测试 APK 内向实际页面提供终止式传输夹具。订单筛选和统计仅覆盖已加载记录，筛选为空时仍可继续分页；失败重试保持原页码，刷新与追加互斥。钱包商品失败的重试重新读取余额与商品，未知余额显示占位。

详情模式、支付与信息区域在初次加载建立占位结构，数据到达立即替换内容；共享边界与圆角采用可中断弹簧。首页常用设备横向惯性滚动时轻触卡片即可停止并进入详情，拖动不触发打开。短信字段声明 SmsOtpCode 自动填充语义并使用数字键盘，是否提供短信建议取决于系统/输入法自动填充服务，不申请读取短信权限。

首页扫码使用原始 primary/onPrimary 配对；二级/状态/图标块保留 secondary 和 tertiary 的灰紫/灰蓝层次。支付渠道选中使用 primary/onPrimary，未选使用 surfaceContainer/onSurfaceVariant；全应用保留完整主题语义，不再执行强制同蓝覆盖。

## 首次使用与功能指南

首次安装、版本新增和主动重看共用 `FeatureGuideScreen` 全屏卡片序列；不再先弹摘要，也没有另一套滚动指南列表。界面采用现有 MaterialExpressiveTheme、强调字号、主题色图形容器、Expressive 按钮和弹簧切换动效，依据 [Material 3 Expressive](https://m3.material.io/) 与 [Motion physics](https://m3.material.io/styles/motion)。卡片逐张前进/返回；只有单卡正文在小屏/大字时可滚动，操作固定在底部。全屏引导窗口及返回页面的系统栏图标分别跟随当前主题，在窗口恢复焦点时重设对比度。

当前指南固定为三张：无广告原生体验、前台慧生活 NFC 卡片（不支持支付宝碰一碰）、默认启动页选择。采用修订 2 的稳定键，已有安装也展示尚未读过的新修订。图标容器 64dp、图标 32dp，使用 Compose 动画缓慢上下浮动；尊重系统动画时长设置。

引导不可跳过，移除跳过按钮。每点下一步持久保存当前已读键，最后点击“开始使用”完成；重启继续未读内容。返回重看前一卡，第一页返回退出应用并保留未读；主动重看同样遵循该规则。小屏/大字正文滚动，底部操作保持可见。已读跨登出/换账号保留，降级保留未知修订键。

更新提示优先，强制更新继续阻止业务；未读指南在 NFC Intent 会话中同样必须完成，之后再处理排队的卡片路由。“我的 → 使用指南”仍可主动重看全部卡片，使用同一全屏界面并保留原页面。引导打开期间暂停前台 NFC 读卡与排队路由，关闭后再处理。引导不申请权限、不跳转到业务、不发起启停或支付。

开发者工具新增“重置引导卡片”：确认后只清本机引导已读进度、将基础状态重置并立即展示全部当前卡片；不清账号、设备记录、外观、更新策略、开发者开关或 NFC 文件。关闭开发者工具后 VM 也拒绝重置。重置后关闭未看完的卡片，下次冷启动继续剩余内容。

新增功能需新增稳定键；重要交互变化才递增修订，普通文案修正保持键不变。删除功能同时清目录与说明，历史已读键可保留，禁止复用。维护时验证首次/已有用户、跨多版本、部分阅读重启、修订替换、降级回升与开发者重置。

### 开发者工具布局

工具页按“界面与引导”“设备诊断”分组，以主题色概览容器、带图标的整行工具卡片和明确的尾部方向标识组织入口；关闭开发者工具使用独立按钮。全部控件采用 Expressive 按钮形变和主题色，长说明可换行，小屏/大字可滚动。NFC 子页独立显示采集状态容器和全宽开始/停止/导出操作，保留原来的显式采集、离页停止与原始记录边界。

账单点击即展示已有摘要，读取期间固定进度槽并禁用支付，关闭后迟到响应不重新打开面板。账单详情打开保留主题空间弹性，关闭保留该空间曲线的刚度与阈值，但阻尼至少为临界阻尼，防止越过 Hidden 后回拉；局部替换 Material3 alpha14 的关闭规格与遮罩效果包络，内部控件仍使用原主题。不指定固定毫秒数，保留系统动画倍率。Material3 面板保留 Android 14 及以上的系统预测性返回。未付账单详情左侧为“暂不支付”、右侧为“去支付”，等宽等高且固定在明细滚动区域之外；大字体允许共同增高。“暂不支付”、标题关闭和系统返回都只关闭面板，保留待付账单，不请求关闭支付交易、不改本地或服务端账单状态。界面说明可稍后回到订单页继续支付；“去支付”仍先关闭详情，再打开支付面板。原版充值账单取消链路尚未查证，不再提供无依据的“取消订单”或取消成功提示，没有添加退款能力；已被服务端取消的历史账单仍按状态 9 展示。

### 卡片与更新来源

页面统一采用 AppLayout 的 16dp 外边距、16dp 卡片内边距、12dp 分组间隔及 56dp 主操作最小高度，图标和行内文字操作保持各自 Material 触控尺寸。在线状态使用绿色、运行中/启动中黄色，浅深色均保持文字对比度，离线保留原中性色。首页常用卡片使用 14dp 内边距、单行名称省略并始终预留徽标，未置顶时隐藏徽标绘制和语义但保留尺寸，避免置顶或名称长短改变高度。首页常用设备、设备列表及“我的”功能卡片使用 surfaceContainerLow，置顶卡使用 surfaceContainer 略加深；首页及设备列表共用带“置顶”文字的图钉徽标，详情操作使用同一图钉。设备页收藏、常用、最近三个列表均在筛选后按置顶优先稳定排序。

选项按钮的选中态使用浅蓝底，未选中保留浅灰底和边界，辅助选项底色进一步减弱。

“我的 → 关于本客户端”检查更新为浅色圆角图标按钮，检查中显示进度并禁止重复点击。按钮上方提供优先源下拉列表：GitHub官方（默认）、gh-proxy(国内加速)。选择为安装偏好，登出保留。手动与自动检查都先尝试优先源，失败依次尝试其余源；备用源返回有效新版本后才询问是否临时切换；镜像版本不得落后于已知官方策略；没有新版本或全部失败时不弹切换确认。拒绝不采用其策略、不下载，同一备用源和版本不会在自动轮询中重复提示，手动检查可重新询问；接受后立即使用该次来源下载，不修改优先源。镜像返回的策略不持久保存，不引入强制门槛；已缓存官方强制策略仍生效。

### 2.x 独立签名迁移

2.0.0 启用独立 release 签名，旧 1.x 更新器拒绝不同证书是预期保护，不修改其验证规则。发布说明和最新策略说明须明确：先结束正在使用的设备并核对账单，再从正式 Release 页面下载新版，卸载旧应用后安装并重新登录；本机最近、常用、置顶和设置随卸载删除。联网取得强制策略的低于 66 版本阻止进入业务；离线或未实现更新门禁的旧版不能由客户端策略远程停用。新安装后，后续 2.x 仍使用同一独立证书覆盖升级。

开发者工具可点击复制当前登录令牌；剪贴板含敏感凭据，应妥善保管。
