## 3. 关键机制

### 3.1 全自动刷新（无手动刷新按钮）

| 触发 | 实现 |
|---|---|
| 打开应用 / 从后台回到前台 | `LifecycleResumeEffect` → `vm.bumpRefresh()` |
| 进入任一页面 / 返回上一页 | `currentBackStackEntryFlow` 等待目标 RESUMED 与共享过渡结束 → `vm.bumpRefresh()`（200ms 合并） |
| 页面响应 | 每个页面 `LaunchedEffect(refreshTick) { load() }`，首帧也会执行 |
| 设备详情 | 同上 + 启动中/运行中每 2s 轮询 `dev/status`（含启动成功后 20s 受限窗口），空闲与异常状态不轮询，仅页面 RESUMED 时运行。`StartCommandLock` 最多 20s，仅在待机、有本设备记录、未见运行态时保护重复启动，状态变化立即解锁；请求忙碌态没有固定冷却 |
| 首页 | `refreshAll()` → `master` + 钱包 + 由账单派生的历史 + 进行中记录对账（`dev/status`） |
| 我的 / 设备 | 我的独立 `refreshMaster()` + `refreshWallet()`；设备 `refreshMaster()`；下拉均调用 `refreshAll()` |

#### 启动确认（`dev/start` 之后）

`code >= 0` 只代表服务端**受理**了命令，不代表机器已离开待机。旧实现把它当成成功直接写
「进行中」，于是没出水的饮水机在首页显示「使用中」，约 12 秒后才被轮询清掉。现行流程：

| 步骤 | 说明 |
|---|---|
| 1 | 启停共用 VM 互斥；`dev/start`（`did/upgrade/ptype/args/rcp=false/cnt`）受理后先保存独立 `pendingStart` 书签；确认任务归属 VM，返回首页不取消，登出/演示切换取消旧账号任务 |
| 2 | 每 2s 读一次 `dev/status`，最多 5 次（首读前 1s 宽限，约 11s 上限）；快照是残缺对象；先检查同 id 且包含在线状态及业务状态，再合并到已知设备（`mergeStatus`）判定，空/异设备/缺字段响应保持未知 |
| 3 | 设备进入 `1/30/10/20`（开机/准备中/运行中/冲洗中）→ 将待确认书签提升为「进行中」并清理待确认；本机计时起点保留受理时间，不等于服务端计费起点 |
| 4 | 一直 `99`（待机）或离线/故障 → 返回 `START_UNCONFIRMED` 并清待确认；状态读取失败/缺失 → 同样不报成功，但保留待确认供后续刷新/重建恢复；不自动重发启动 |
| 5 | 未确认时不再伪造「使用中」：首页/订单卡片的胶囊只来自服务端快照，首帧显示「同步中」；`refreshAll()` 与回前台会用 `dev/status` 对账本机记录 |
| 范围 | 第 2–4 步只对状态可观测的设备族生效（`StartWatch.isObservable`：水控/淋浴/饮水机、洗衣/烘干/洗鞋、吹风机、充电桩）。消费机/售货机/门禁可能在 `99` 下就能用，仍按「服务端受理」记录，避免误报失败 |
| 结束 | 机身仍在运行时 `dev/end` 返回 `-2`「请在设备上点击结算」；客户端保留记录并提示，等设备回到 `99` 再清除 |
| 状态模型 | `dev/status` 按 `StatusSnapshot`/`DeviceStatus`（局部）建模，`Api.deviceStatus` 不再返回 `DeviceDetail`；详情页走 `pollDevice(did, base)`、其余路径各自持有已知设备，统一经 `Device.mergeStatus` 合并 |
| 类型缺失 | 账单/收藏/最近等可能拿到局部设备的地方，类型标签用 `DeviceType.nameOrNull()` 回退「设备/—」，不用会得到「智能设备」的 `name()` |

#### 进行中轮询（首页“使用中”卡片 / 订单“使用中”分栏）

| 项 | 说明 |
|---|---|
| 触发 | 本机存在「进行中的使用」或待确认书签，且 App 处于前台；命令确认期间由命令独占读状态 |
| 周期 | 每 **2s** 调一次 `GET /ui/app/dev/status?did=&more=false`（实际间隔 = 请求耗时 + 2s） |
| 展示 | 卡片状态胶囊取服务端 `gene.status`（运行中 / 冲洗中 / 启动中 / 离线 / 禁用…），并显示「服务端 HH:mm:ss」；没有快照时显示「同步中」，不显示「使用中」 |
| 结束判定 | 只以同设备完整状态的待机/异常清除书签；未知、空/异设备/缺字段响应不清除。详情、全局轮询与刷新复用同一对账函数，命令前迟到响应按修订号丢弃，账号变化按令牌丢弃 |
| 对账 | 每次 `refreshAll()`、回前台与启动时各补一次 `dev/status`：待机/异常即清除本机记录，不等轮询循环 |
| 让位 | 打开该设备详情页时暂停（详情页自己 2s 轮询并回传 VM）；异步首载、运行态和命令忙碌变化重新评估详情轮询，避免首载时无设备导致循环退出后不再启动 |
| 后台 | `onPause` 取消任务、不再发请求；回前台立即补一次再继续 |
| 边界 | 不驻留后台、不起 Service、不申请额外权限；预览模式不轮询 |
刷新是**静默**的：已有数据时不显示整页 Loading，只在首次进入显示；这样返回页面不会闪白。

页面与根布局的 Flow 使用 `collectAsStateWithLifecycle()`，生命周期停止时暂停 UI 收集。首页/订单的进行中用时由独立 `UsageDuration` 文本每秒更新，仅在目标页面 RESUMED 时计时，避免计时触发整页重组，返回后按当前时间补齐。首页排序与设备页关联使用按 id 的索引；过滤和类型集合按数据/筛选条件缓存，搜索输入只重算过滤结果。下拉刷新入口防重复并在 `finally` 释放指示状态，主数据加载也在取消时释放状态，丢弃账号变化或进入演示前发出的旧主数据响应。这些改动不改变服务端计费、设备状态和命令确认规则；真机帧率与耗电改善仍需实测。

### 3.2 历史数据来自云端

原应用没有本地"最近设备"表。最接近的云端数据是**账单历史**（每条 `BillData` 都带 `dev`）：

```
GET /api/v1/bill/lst-owner?page=0&size=50   # 服务端 page 从 0 开始
  → 按 bill.dev.id 聚合：次数、最近时间、设备快照
  → 与"仅扫码未使用"的设备（本地）合并
  → 写入本地索引，供首页"常用设备/最近使用"、设备页"常用/最近"排序
```

> 分页基准：UI 第 1 页必须传 `page=0`，传 1 会被服务端当成第二页而返回空列表。

收藏本身完全由服务端下发（`master.favos`），本地只缓存快照做首屏。

### 3.3 手动输入编号

「手动输入」是独立页面：输入设备贴纸编号或二维码里的 `id`，走与扫码完全相同的链路：

```
QrParser.parse(text) → GET /api/v1/qr/use?id=<id> → 按 QrFlow 校验 qr.type / dev → 设备详情
```

纯数字按原应用规则识别为"编号/充值卡"类型，但最终是否进入设备页由服务端 `qr.type` 与 `dev` 决定：明确的非设备类型拒绝，缺类型但有可用设备时按设备处理。

### 3.4 支付宝支付

与原客户端相同的三段式：

```
GET /api/v1/bill/pay/channels?id=<billId>        // 可用渠道
GET /api/v1/trans/prepay/21?id=<billId>          // data 可为空（免密），或为签名订单串
PayTask(activity).payV2(orderInfo, true)          // 仅有订单串时拉起 SDK
GET /api/v1/trans/confirm?id=<billId>             // 服务端确认
```

**关于"逆向原 APK 的签名"**：支付宝 APP 支付**不使用 APK 签名**。安全链条是——

1. 服务端用**商户私钥**对 `orderInfo` 签名（`app_id`、`biz_content`、`sign`）；
2. 客户端只把这个字符串交给支付宝 SDK，SDK 与支付宝 App 校验商户签名；
3. 支付结果再由服务端 `trans/confirm` 反向确认。

因此"复用原 APK 签名"既无必要也不可行；正确做法就是集成官方 SDK 并复用服务端下发的订单串，本项目即按此实现。余额/钱包（`91/92/93`）无需 SDK，服务端直接扣款；微信 SDK 已集成，仍需包名/签名/appId 匹配；云闪付/银行 SDK 未集成。签约使用协议类型 20 的 `sign`，不是支付渠道 21，也不从 `acc-pgas` 推断签约状态。

### 3.5 错误与令牌

`code=-99` → 清会话 → 登录页 + Snackbar；`-87/-88/-52/-28` → 引导充值/支付；网络失败 → 内联错误（切页/返回即自动重试）。
